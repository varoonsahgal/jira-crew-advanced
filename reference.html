R7 Release quality checklist

Proceed when evidence covers the scope and no High defect is open in the path users see. Hold when a known failure or missing evidence affects that path. Clarify when the scope or the criterion itself is unclear; say exactly what you need and from whom.

R8 Zephyr and eazyBI glossary

Test case
A reusable test with steps and expected results, linked to the requirement (Story) it verifies.
Test step
One action and its expected result inside a test case.
Test cycle
A set of test executions for a release, build or sprint.
Execution status
Pass, Fail, Blocked, Not Executed, In Progress.
Coverage
Which requirements and criteria have linked test cases, and whether those were executed.
Traceability
The chain requirement → test case → execution → defect, readable in both directions.
Retest
A new execution of a failed test on a build that contains the fix. History keeps every earlier execution.
Regression selection
The tests to rerun after a change: the failure, plus tests touching the changed behaviour.
Measure
A number the report calculates, such as “Sprint story points completed”. Its definition decides which items count.
Dimension
A way to slice measures: Sprint, Team, Issue Type, Status.
Sprint issues committed
Items in the sprint at its start.
Sprint issues added
Items added after the sprint started (CRW-21 in SWP q4.2).
Sprint issues completed
Items counted as completed at sprint close, under the measure's definition.
Sprint story points committed / completed
The same, summed in story points.
Drill through issue
Open the list of keys behind one cell.
Last import time
When the report last loaded Jira data. Anything that changed after it isn't in the report.

R9 Git key conventions

The provider links activity to Jira by finding the work item key. Use the key exactly as Jira shows it, in capitals.

WhereConventionExample
BranchKey first, then a short slugCRW-25-trip-board-swap
CommitKey at the start of the messageCRW-25 Add swap button to trip card
Pull requestKey in the titleCRW-25 Submit a swap request from the trip board
Your seatSame pattern with your seat's Ready storyCRP-?-swap-eligibility
  • Wrong key already pushed? Don't rewrite shared history. Put the correct key in the pull request title or a new commit, and note the mistake on the wrongly linked item.
  • Missing key on a local, unpushed commit? Amend it before you push.
  • Smart commits write to Jira as you. Use #comment sparingly; never transition work from Git past eQE Testing or PO Review.

If activity doesn't appear

  1. Was it pushed? Local commits never sync.
  2. Is the key correct, uppercase and in a field the provider reads?
  3. Is the repository selected in the integration and has the backfill or sync finished?
  4. Can you see it? Viewing development information needs the View Development Tools permission and access to the repository.
  5. Still missing: route to the app owner (integration and sync) or repository owner (access), with the commit link and time.

On the training site no Git provider is connected; practise in the Module 5 replica.
